# Bash: основы написания надёжных shell-скриптов

## 1. Shell и Bash

Shell — программа, которая принимает команды пользователя и запускает другие
программы. Она одновременно является интерактивной командной оболочкой и языком
автоматизации.

Bash расшифровывается как Bourne Again Shell. Он развивает идеи исторической
оболочки `sh` и распространён в Linux. Bash поддерживает переменные, условия,
циклы, функции, перенаправления, конвейеры, управление заданиями и историю
команд.

Есть два основных режима работы:

- интерактивный — команды вводятся в терминале;
- неинтерактивный — команды читаются из файла сценария.

Bash особенно полезен для объединения системных утилит: получить информацию,
отфильтровать её, проверить условие, вызвать службу и сохранить результат. Для
сложной обработки данных или большого приложения обычно удобнее Python или
другой язык общего назначения.

## 2. Первый скрипт

Shell-скрипт — текстовый файл с командами. Первая строка может содержать shebang:

```bash
#!/usr/bin/env bash

printf '%s\n' 'Hello from Bash'
```

Shebang указывает, каким интерпретатором запускать исполняемый файл. Вариант
`/usr/bin/env bash` ищет Bash в `PATH`; `#!/bin/bash` использует фиксированный
путь и предсказуемее в контролируемой Linux-среде.

Сделать файл исполняемым и запустить:

```bash
chmod +x script.sh
./script.sh
```

Также можно явно вызвать интерпретатор без изменения прав:

```bash
bash script.sh
```

Запуск через `sh script.sh` не гарантирует Bash: `/bin/sh` может указывать на
другую POSIX-оболочку, не поддерживающую конструкции `[[ ... ]]`, массивы и
другие возможности Bash.

## 3. Команды, коды завершения и логические связки

Каждая команда возвращает целый код завершения. `0` означает успех, любое
ненулевое значение — ошибку или отрицательный результат проверки.

```bash
command
printf 'exit status: %s\n' "$?"
```

Код последней команды доступен в `$?`. Обычно лучше проверять команду напрямую:

```bash
if mkdir -- "$directory"; then
    printf 'Directory created\n'
else
    printf 'Cannot create directory\n' >&2
fi
```

Логические операторы используют код завершения:

```bash
command1 && command2  # command2 только после успеха command1
command1 || command2  # command2 только после ошибки command1
```

`exit 0` завершает скрипт успешно, `exit 1` — с общей ошибкой. Для разных видов
ошибок можно использовать разные ненулевые коды.

## 4. Переменные и раскрытие значений

При присваивании вокруг `=` не ставят пробелы:

```bash
name='server-01'
count=3
```

Значение раскрывается через `$name` или `${name}`:

```bash
printf 'Host: %s\n' "$name"
printf 'Log: %s\n' "${name}.log"
```

По умолчанию переменные Bash хранят строки. Арифметический контекст позволяет
работать с целыми числами:

```bash
count=$((count + 1))
```

Командная подстановка сохраняет стандартный вывод команды в переменную и
удаляет завершающие переводы строк:

```bash
current_user=$(whoami)
kernel=$(uname -r)
```

## 5. Кавычки — основа корректного Bash

Без кавычек результат раскрытия переменной подвергается разделению на слова и
подстановке шаблонов файловой системы. Поэтому почти всегда нужно писать
`"$variable"`.

```bash
path='My Documents/report.txt'
rm -- "$path"
```

Виды кавычек:

- одинарные `'...'` сохраняют содержимое буквально;
- двойные `"..."` разрешают `$variable`, `$(command)` и некоторые escape-
  последовательности;
- отсутствие кавычек включает дополнительное разбиение и globbing.

`--` сообщает многим утилитам конец опций. Это защищает значение, начинающееся
с дефиса, от ошибочной интерпретации как флага.

```bash
printf '%s\n' "$value"
find -- "$directory" -type f
```

Для вывода обычно предпочтительнее `printf`, потому что поведение `echo` с
`-n`, `-e` и обратными слешами зависит от реализации.

## 6. Позиционные параметры

Аргументы командной строки доступны через специальные параметры:

- `$0` — имя скрипта;
- `$1`…`$9` — отдельные аргументы;
- `${10}` и далее — параметры с многозначным номером;
- `$#` — количество аргументов;
- `"$@"` — все аргументы с сохранением их границ;
- `"$*"` — все аргументы как одна строка;
- `shift` — удалить первый аргумент и сдвинуть остальные.

```bash
if (( $# != 1 )); then
    printf 'Usage: %s DIRECTORY\n' "$0" >&2
    exit 2
fi

directory=$1
```

Для передачи аргументов другой функции или команде почти всегда используют
`"$@"`:

```bash
process_arguments "$@"
```

## 7. Условия и проверки

Bash предлагает старую конструкцию `[ ... ]` и расширенную `[[ ... ]]`.
В Bash-скриптах `[[ ... ]]` безопаснее для сложных строковых условий и
поддерживает регулярные выражения.

```bash
if [[ -z $value ]]; then
    printf 'Value is empty\n'
elif [[ $value == 'start' ]]; then
    printf 'Starting\n'
else
    printf 'Unknown value\n'
fi
```

Частые проверки:

```bash
[[ -z $value ]]       # пустая строка
[[ -n $value ]]       # непустая строка
[[ -e $path ]]        # объект существует
[[ -f $path ]]        # обычный файл
[[ -d $path ]]        # каталог
[[ -L $path ]]        # символическая ссылка
[[ -r $path ]]        # доступен для чтения
[[ -w $path ]]        # доступен для записи
[[ -x $path ]]        # доступен для исполнения/прохода
[[ $left == $right ]] # строки равны
```

Для целочисленных выражений удобнее `(( ... ))`:

```bash
if (( count < 1 || count > 6 )); then
    printf 'Count must be from 1 to 6\n' >&2
    exit 2
fi
```

Регулярное выражение справа от `=~` обычно не заключают целиком в кавычки:

```bash
if [[ $value =~ ^[0-9]+$ ]]; then
    printf 'Only decimal digits were provided\n'
fi
```

`^[0-9]+$` означает: от начала до конца строки должна находиться одна или более
цифр. Это не универсальная проверка числа: она не допускает знак, дробную часть
и экспоненту. Формат нужно определять требованиями программы.

### Сопоставление через `case`

Когда вариантов несколько, `case` читается лучше цепочки `if`:

```bash
case $answer in
    [Yy]) save_report ;;
    [Nn]) exit 0 ;;
    *)
        printf 'Expected Y or N\n' >&2
        exit 2
        ;;
esac
```

Шаблоны `case` — glob-шаблоны, а не регулярные выражения.

## 8. Функции и модульная структура

Функция группирует связанную логику:

```bash
print_error() {
    printf 'Error: %s\n' "$1" >&2
}
```

Аргументы функции доступны внутри неё как `$1`, `$2` и `"$@"`. Переменные по
умолчанию глобальны даже при создании внутри функции, поэтому для временных
значений используют `local`:

```bash
make_filename() {
    local timestamp
    timestamp=$(date '+%Y-%m-%d_%H-%M-%S')
    printf '%s.status\n' "$timestamp"
}
```

Функция возвращает код через `return`, но не произвольную строку. Данные обычно
передают через стандартный вывод и командную подстановку:

```bash
filename=$(make_filename)
```

Большой скрипт можно разделить на файлы и подключить их:

```bash
source "${script_dir}/lib/system_info.sh"
```

`source` выполняет содержимое файла в текущей оболочке. Поэтому подключать
непроверенный файл опасно. Кроме того, путь следует вычислять относительно
самого скрипта, а не текущего рабочего каталога пользователя:

```bash
script_dir=$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)
source "${script_dir}/lib/system_info.sh"
```

## 9. Стандартные потоки и перенаправления

У процесса обычно есть три стандартных потока:

- `stdin` (`0`) — ввод;
- `stdout` (`1`) — обычный результат;
- `stderr` (`2`) — диагностика и ошибки.

```bash
command >output.txt       # перезаписать stdout
command >>output.txt      # добавить stdout
command 2>error.log       # записать stderr
command >all.log 2>&1     # оба потока в один файл
command </path/input.txt  # stdin из файла
```

Ошибки скрипта следует писать в `stderr`:

```bash
printf 'Directory does not exist: %s\n' "$directory" >&2
```

Это позволяет отдельно обрабатывать машинный результат и диагностику.

Here document передаёт многострочный ввод:

```bash
cat <<EOF
Host: $hostname
Date: $current_date
EOF
```

Если разделитель заключить в кавычки (`<<'EOF'`), переменные внутри не
раскрываются.

## 10. Конвейеры

Конвейер передаёт stdout одной команды в stdin следующей:

```bash
ip route show | awk '/default/ {print $3; exit}'
```

Каждая программа выполняет небольшую операцию, а их композиция решает более
сложную задачу. Часто используются:

- `grep` — отбор строк;
- `cut` — выбор разделённых полей;
- `sort` — сортировка;
- `uniq` — обработка соседних повторов;
- `head` и `tail` — начало и конец потока;
- `wc` — подсчёт строк, слов или байтов;
- `awk` — обработка полей и вычисления;
- `sed` — потоковое преобразование текста.

Не следует разбирать предназначенный для людей вывод команды, если существует
машиночитаемый режим или структурированный источник. Например, информацию об ОС
надёжнее читать из `/etc/os-release`, а адреса — через специализированные опции
`ip`.

По умолчанию код конвейера равен коду последней команды. Опция `pipefail`
позволяет заметить ошибку на более раннем этапе.

## 11. Строгий режим и обработка ошибок

Часто в начале скрипта включают:

```bash
set -Eeuo pipefail
```

- `-e` завершает скрипт при многих необработанных ошибках;
- `-u` считает обращение к несуществующей переменной ошибкой;
- `-o pipefail` замечает ошибки внутри конвейера;
- `-E` помогает наследовать ловушку `ERR` функциями.

Это не заменяет продуманную обработку ошибок: у `set -e` есть исключения в
условиях, логических цепочках и других конструкциях. Ожидаемую ошибку лучше
проверять явно.

Временные ресурсы очищают через `trap`:

```bash
temporary_file=$(mktemp)
trap 'rm -f -- "$temporary_file"' EXIT
```

В строке ловушки важны кавычки: нужно понимать, раскрывается переменная при
объявлении `trap` или при его выполнении.

## 12. Получение информации о Linux-системе

Системный отчёт лучше строить из специализированных источников:

```bash
hostname_value=$(hostname)
timezone=$(timedatectl show --property=Timezone --value)
current_user=$(id -un)
os_name=$(. /etc/os-release && printf '%s' "$PRETTY_NAME")
current_date=$(date '+%d %B %Y %H:%M:%S')
uptime_human=$(uptime -p)
uptime_seconds=${SECONDS}
default_gateway=$(ip route show default | awk 'NR == 1 {print $3}')
```

`$SECONDS` показывает время жизни текущей оболочки, а не обязательно всей
системы. Системный uptime можно читать из `/proc/uptime` или получить подходящей
утилитой.

При выборе IP-адреса нельзя бездумно брать «первый» или «последний» интерфейс:
на машине могут быть loopback, VPN, контейнерные и несколько физических сетей.
Лучше явно выбрать интерфейс или определить адрес, используемый для маршрута к
нужному назначению:

```bash
ip route get 1.1.1.1
```

Префикс `/24` — не десятичная маска. Если отчёту нужна именно
`255.255.255.0`, префикс необходимо корректно преобразовать, например с помощью
`ipcalc` или собственной проверенной функции.

## 13. Память, диски и единицы измерения

`free` сообщает о памяти, а `df` — о файловых системах:

```bash
free --bytes
df --block-size=1 /
```

Для расчётов лучше запросить байты или фиксированные блоки и только затем
форматировать значение. Это надёжнее разбора локализованного `-h`-вывода.

В единицах есть два соглашения:

- десятичные: `1 MB = 1 000 000` байт, `1 GB = 1 000 000 000` байт;
- двоичные: `1 MiB = 1 048 576` байт, `1 GiB = 1 073 741 824` байт.

Если результат делится на `1024`, корректнее подписывать его `MiB` или `GiB`.
Форматирование выполняет `awk`:

```bash
awk -v bytes="$bytes" 'BEGIN {printf "%.3f GiB\n", bytes / 1024^3}'
```

## 14. Сохранение отчёта

Интерактивный ввод читает builtin `read`:

```bash
read -r -p 'Save report? [y/N] ' answer
```

Флаг `-r` запрещает интерпретировать обратные слеши. Если Enter должен означать
«нет», это отражают в подсказке `[y/N]`.

Имя файла по времени можно построить так:

```bash
filename=$(date '+%Y-%m-%d_%H-%M-%S.status')
```

Если скрипт сначала выводит отчёт, а затем должен сохранить ровно тот же текст,
удобно сформировать отчёт один раз в переменной или временном файле. Иначе
команды выполнятся повторно и значения времени или нагрузки могут измениться.

Нельзя хранить произвольные бинарные данные в переменной Bash: командная
подстановка не поддерживает нулевые байты. Для обычного текстового отчёта это не
проблема.

## 15. ANSI-цвета в терминале

Терминалы поддерживают управляющие ANSI-последовательности. Например, код `31`
задаёт красный текст, `41` — красный фон, а `0` сбрасывает оформление.

```bash
printf '\033[41;37m%s\033[0m\n' ' white on red '
```

Цветовые коды удобно сопоставить логическим именам через `case`:

```bash
foreground_code() {
    case $1 in
        white) printf '37' ;;
        red)   printf '31' ;;
        green) printf '32' ;;
        blue)  printf '34' ;;
        *) return 1 ;;
    esac
}
```

Перед применением схемы нужно проверить:

- допустимость всех значений;
- наличие нужного числа параметров;
- различие цвета текста и фона;
- поддержку цвета терминалом.

Цвет нельзя делать единственным носителем смысла: вывод может попасть в файл,
CI-журнал или терминал пользователя с нарушением цветового восприятия.
Проверить, направлен ли stdout в терминал, можно через `[[ -t 1 ]]`.

## 16. Конфигурационные файлы

Значение по умолчанию подставляется через parameter expansion:

```bash
background=${column1_background:-black}
font_color=${column1_font_color:-white}
```

Оператор `:-` использует default, если переменная отсутствует или пуста. Вариант
`-` без двоеточия считает пустую строку заданным значением.

Простой файл вида `key=value` иногда подключают через `source`, но это выполняет
весь файл как Bash-код:

```bash
source ./colors.conf
```

Так допустимо только для полностью доверенного файла, который фактически
является shell-кодом. Пользовательскую конфигурацию безопаснее разбирать как
данные: читать строки, разрешать только известные ключи и проверять значения.

```bash
while IFS='=' read -r key value; do
    [[ -z $key || $key == \#* ]] && continue

    case $key in
        column1_background) column1_background=$value ;;
        column1_font_color) column1_font_color=$value ;;
        *) printf 'Unknown setting: %s\n' "$key" >&2; exit 2 ;;
    esac
done <"$config_file"
```

Этот минимальный формат ещё требует решения о пробелах, пустых значениях,
комментариях и допустимых символах. Формат конфигурации должен быть явно
определён.

## 17. Поиск объектов через `find`

`find` рекурсивно обходит дерево каталогов и проверяет условия:

```bash
find -- "$directory" -type d
find -- "$directory" -type f -name '*.conf'
find -- "$directory" -type f -perm /111
find -- "$directory" -type l
```

Шаблон `*.conf` заключают в кавычки, чтобы его обрабатывал `find`, а не текущая
оболочка до запуска команды.

Основные типы:

- `-type f` — обычный файл;
- `-type d` — каталог;
- `-type l` — символическая ссылка.

`-executable` зависит от пользователя, запустившего `find`, и его прав. Проверка
битов исполнения через `-perm /111` отвечает на другой вопрос: установлен ли
хотя бы один execute-бит.

Следует учитывать:

- ошибки доступа к каталогам;
- переходы между файловыми системами (`-xdev` при необходимости);
- символические ссылки и выбранную политику их обхода;
- имена с пробелами, переводами строк и дефисами;
- гонки, если дерево меняется во время анализа.

Перенаправление `2>/dev/null` скрывает ошибки, но может создать ложное ощущение
полного результата. Для административного отчёта лучше сообщить, что часть
дерева недоступна.

## 18. Размеры каталогов и сортировка

Размеры верхнего уровня можно получить через `du`:

```bash
du -x --max-depth=1 --bytes -- "$directory"
```

Далее числовые значения сортируют:

```bash
du -x --max-depth=1 --bytes -- "$directory" |
    sort -nr |
    head -n 5
```

Сортировка вывода `du -h` через `sort -h` удобна для человека, но зависит от
поддержки human-readable суффиксов. Для вычислений надёжнее сортировать байты и
форматировать только окончательный результат.

Размер каталога включает вложенное содержимое, поэтому родитель и дочерний
каталог перекрываются. «Самые большие каталоги» может означать суммарный размер
поддерева или размер только непосредственных файлов — эти метрики нужно не
смешивать.

## 19. Безопасная обработка имён файлов

Разбор строк через `for file in $(find ...)` некорректен: пробелы и переводы
строк разрушают границы имён. Надёжный Unix-способ — разделитель NUL:

```bash
find -- "$directory" -type f -print0 |
while IFS= read -r -d '' file; do
    printf '%s\n' "$file"
done
```

Поддерживающие NUL утилиты часто имеют опции `-0` или `-z`, например
`sort -z`. Однако не все команды одинаково поддерживают этот режим, поэтому
сложный отчёт иногда лучше реализовать на Python.

Тип файла нельзя надёжно определять только по расширению: файл без расширения
может быть текстовым или исполняемым, а `.txt` может содержать произвольные
байты. Возможны две разные классификации:

- по имени и расширению — `find -name '*.log'`;
- по содержимому — утилита `file` и MIME-тип.

Следует заранее выбрать определение, соответствующее цели отчёта.

## 20. Хеширование файлов

Хеш-функция преобразует содержимое файла в значение фиксированной длины:

```bash
md5sum -- "$file"
sha256sum -- "$file"
```

Одинаковый хеш с очень высокой вероятностью означает одинаковое содержимое.
Изменение даже одного байта обычно полностью меняет хеш.

MD5 больше не считается криптографически безопасным из-за известных коллизий.
Он может использоваться как быстрая контрольная сумма в совместимом формате,
но для проверки целостности в контексте безопасности предпочтительнее SHA-256.
Простой хеш без цифровой подписи или доверенного канала не защищает от
злоумышленника, который способен заменить и файл, и ожидаемый хеш.

Хеширование больших файлов читает всё их содержимое и может быть дорогой
операцией. Если нужны хеши только десяти крупнейших исполняемых файлов, сначала
следует выбрать эти файлы по размеру и лишь затем вычислять хеши.

## 21. Измерение времени выполнения

Bash предоставляет переменную `SECONDS` с целым количеством секунд с момента
запуска оболочки:

```bash
SECONDS=0
perform_analysis
printf 'Elapsed: %s seconds\n' "$SECONDS"
```

Для большей точности GNU `date` поддерживает наносекунды:

```bash
start=$(date +%s.%N)
perform_analysis
end=$(date +%s.%N)
elapsed=$(awk -v start="$start" -v end="$end" \
    'BEGIN {printf "%.3f", end - start}')
```

`%N` не определён стандартом POSIX и работает не во всех реализациях `date`, в
частности отличается на macOS. Для переносимого измерения следует использовать
доступный в целевой среде инструмент. Внешняя команда `time` отдельно измеряет
реальное, пользовательское и системное время процесса.

## 22. Проверка качества скриптов

До запуска скрипт можно проверить синтаксически:

```bash
bash -n script.sh
```

ShellCheck выполняет статический анализ и находит частые ошибки с кавычками,
массивами, путями и перенаправлениями:

```bash
shellcheck script.sh
```

Для трассировки выполнения:

```bash
bash -x script.sh
```

Трассировка может раскрыть пароли, токены и другие секреты, поэтому её нельзя
бездумно включать в production-журналах.

Проверять следует не только обычный сценарий, но и границы:

- аргументы отсутствуют или их слишком много;
- значение пустое или содержит пробелы;
- путь начинается с `-`;
- каталог не существует или недоступен;
- конфигурация частичная или содержит неизвестный ключ;
- команда отсутствует;
- вывод направлен не в терминал;
- файловая система меняется во время обхода.

## 23. Рекомендуемая структура небольшого проекта

```text
system-report/
├── bin/
│   └── system-report
├── lib/
│   ├── collect.sh
│   ├── format.sh
│   └── validate.sh
├── config/
│   └── colors.conf
├── tests/
└── README.md
```

Главный файл отвечает за последовательность действий, а функции — за отдельные
обязанности:

1. разобрать и проверить аргументы;
2. загрузить и проверить конфигурацию;
3. собрать данные;
4. сформировать вывод;
5. при необходимости сохранить результат;
6. вернуть корректный код завершения.

Не нужно делить короткий скрипт на множество файлов только ради структуры.
Модульность полезна, когда уменьшает дублирование и делает части независимо
проверяемыми.

## 24. Основные правила надёжного Bash

- Заключайте раскрытия переменных в двойные кавычки: `"$value"`.
- Передавайте список аргументов через `"$@"`.
- Используйте `printf` для предсказуемого вывода.
- Отделяйте обычный результат (`stdout`) от ошибок (`stderr`).
- Проверяйте количество, формат и смысл входных данных.
- Используйте `local` для временных переменных функций.
- Не разбирайте имена файлов по пробелам и переводам строк.
- Не скрывайте диагностические сообщения без понимания последствий.
- Подключайте через `source` только доверенный shell-код.
- Предпочитайте машиночитаемый интерфейс человекочитаемому выводу.
- Проверяйте скрипты через `bash -n` и ShellCheck.
- Документируйте внешние команды, GNU-зависимости и целевую платформу.

Bash становится надёжным не из-за количества команд, а благодаря аккуратной
работе с кавычками, потоками, кодами завершения, входными данными и особенностями
файловой системы.
