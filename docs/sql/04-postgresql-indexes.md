# PostgreSQL. Индексы и оптимизация запросов

## Что такое индекс

**Индекс** — это специальная структура данных, которая позволяет PostgreSQL
находить нужные строки значительно быстрее, чем при полном просмотре таблицы.

Без индекса сервер вынужден последовательно просматривать каждую строку таблицы
(Sequential Scan). Если таблица содержит миллионы записей, такой поиск
становится очень медленным.

После создания индекса PostgreSQL может использовать структуру B-Tree и
выполнять поиск за логарифмическое время.

Пример:

- Без индекса — просмотр 1 000 000 строк.
- С индексом B-Tree — поиск выполняется примерно за `log₂(n)` операций.

Именно поэтому индексы значительно ускоряют выполнение запросов.

---

# Когда индекс не используется

Наличие индекса **не гарантирует**, что PostgreSQL будет его использовать.

Планировщик запросов самостоятельно выбирает наиболее эффективный способ
выполнения запроса.

Иногда последовательное сканирование оказывается быстрее, чем использование
индекса.

Например:

- таблица очень маленькая;
- запрос возвращает большую часть строк;
- стоимость чтения индекса выше стоимости полного просмотра таблицы.

Для проверки работы индекса можно временно отключить последовательное
сканирование:

```sql
SET enable_seqscan = off;
```

После этого PostgreSQL будет стараться использовать индекс там, где это
возможно.

> Использовать `enable_seqscan = off` следует только для обучения и анализа
> производительности. В реальных проектах менять этот параметр обычно не
> требуется.

# EXPLAIN ANALYZE

Для анализа выполнения запроса используется команда

```sql
EXPLAIN ANALYZE
```

Она показывает:

- каким способом выполняется запрос;
- используются ли индексы;
- какие операции выполняются;
- сколько времени занял каждый этап;
- реальное время выполнения.

Пример:

```sql
EXPLAIN ANALYZE
SELECT *
FROM person;
```

Если используется индекс, в плане можно увидеть:

```
Index Scan
```

Если индекс не используется:

```
Seq Scan
```

# Индекс B-Tree

Самый распространённый тип индекса в PostgreSQL.

Создаётся командой

```sql
CREATE INDEX имя_индекса
ON таблица USING btree (столбец);
```

Например:

```sql
CREATE INDEX idx_menu_pizzeria_id
ON menu USING btree (pizzeria_id);
```

Такой индекс ускоряет поиск по полю `pizzeria_id`.

Аналогично можно индексировать другие столбцы:

```sql
CREATE INDEX idx_person_order_person_id
ON person_order USING btree (person_id);

CREATE INDEX idx_person_order_menu_id
ON person_order USING btree (menu_id);

CREATE INDEX idx_person_visits_person_id
ON person_visits (person_id);

CREATE INDEX idx_person_visits_pizzeria_id
ON person_visits (pizzeria_id);
```

# Индексы при JOIN

Во время соединения таблиц PostgreSQL постоянно ищет совпадающие значения
ключей.

Например:

```sql
SELECT
    m.pizza_name,
    pz.name
FROM menu m
JOIN pizzeria pz
ON pz.id = m.pizzeria_id;
```

Если поле соединения индексировано, поиск выполняется значительно быстрее.

Чаще всего индексируют:

- первичные ключи;
- внешние ключи.

---

# Индексы по выражению (Expression Index)

Индекс можно строить не только по столбцу, но и по результату выражения.

Например:

```sql
CREATE INDEX idx_person_name
ON person (upper(name));
```

Теперь запрос

```sql
SELECT name
FROM person
WHERE upper(name) = 'ANNA';
```

может использовать индекс.

Без такого индекса PostgreSQL пришлось бы вычислять `upper()` для каждой строки
таблицы.

Expression Index особенно полезен для:

- поиска без учёта регистра;
- индексации вычисляемых выражений;
- функций над столбцами.

---

# Составные (Composite) индексы

Индекс может содержать сразу несколько столбцов.

Например:

```sql
CREATE INDEX idx_person_order_multi
ON person_order
(
    person_id,
    menu_id,
    order_date
);
```

Такой индекс эффективен для запросов:

```sql
WHERE person_id = ...
AND menu_id = ...
```

или

```sql
WHERE person_id = ...
AND menu_id = ...
AND order_date = ...
```

## Порядок столбцов имеет значение

Индекс

```text
(person_id, menu_id, order_date)
```

подходит для поиска:

✅

```sql
WHERE person_id = ...
```

✅

```sql
WHERE person_id = ...
AND menu_id = ...
```

✅

```sql
WHERE person_id = ...
AND menu_id = ...
AND order_date = ...
```

Но плохо подходит для

```sql
WHERE menu_id = ...
```

поскольку поиск начинается с первого столбца индекса.

Поэтому порядок столбцов необходимо выбирать исходя из наиболее частых запросов.

---

# Уникальные индексы

Уникальный индекс гарантирует отсутствие дубликатов.

Создаётся так:

```sql
CREATE UNIQUE INDEX idx_menu_unique
ON menu
(
    pizzeria_id,
    pizza_name
);
```

Теперь в одной пиццерии нельзя добавить две пиццы с одинаковым названием.

Например:

| pizzeria_id | pizza_name   |
| ----------- | ------------ |
| 1           | Cheese Pizza |

повторно добавить уже нельзя.

Но

| pizzeria_id | pizza_name   |
| ----------- | ------------ |
| 2           | Cheese Pizza |

добавить можно, потому что другая пиццерия.

Уникальные индексы часто используются для обеспечения бизнес-правил приложения.

---

# Частичные индексы (Partial Index)

Иногда индекс нужен только для части строк таблицы.

В этом случае используется условие `WHERE`.

Пример:

```sql
CREATE UNIQUE INDEX idx_person_order_order_date
ON person_order
(
    person_id,
    menu_id
)
WHERE order_date = DATE '2022-01-01';
```

Теперь индекс содержит **только записи за 1 января 2022 года**.

Запрос

```sql
SELECT
    person_id,
    menu_id
FROM person_order
WHERE order_date = DATE '2022-01-01';
```

может использовать этот индекс.

Преимущества:

- меньший размер;
- быстрее обновляется;
- ускоряет запросы по определённому условию.

---

# Индексы и оконные функции

Оконные функции сами по себе индекс не используют.

Однако индекс может помочь операциям:

- сортировки;
- группировки;
- разбиения данных.

Например:

```sql
SELECT
    m.pizza_name,
    MAX(pz.rating) OVER (
        PARTITION BY pz.rating
        ORDER BY pz.rating
    )
FROM menu m
JOIN pizzeria pz
ON pz.id = m.pizzeria_id;
```

Если создать индекс

```sql
CREATE INDEX idx_1
ON pizzeria (rating);
```

PostgreSQL может выполнять сортировку эффективнее.

Но это зависит от плана выполнения.

Поэтому всегда следует проверять результат через

```sql
EXPLAIN ANALYZE
```

# Практические рекомендации

- Индексируйте столбцы, которые часто используются в `WHERE`.
- Индексируйте внешние ключи (`FOREIGN KEY`).
- Индексируйте столбцы, участвующие в `JOIN`.
- Не создавайте индексы без необходимости — каждый индекс занимает место на
  диске и замедляет операции `INSERT`, `UPDATE` и `DELETE`.
- Проверяйте эффективность индексов с помощью `EXPLAIN ANALYZE`.
- При создании составного индекса тщательно выбирайте порядок столбцов.
- Используйте частичные индексы, если запросы работают только с небольшой частью
  данных.
- Используйте уникальные индексы для обеспечения целостности данных.

# Основные команды

Создание обычного индекса

```sql
CREATE INDEX idx_name
ON table (column);
```

Создание уникального индекса

```sql
CREATE UNIQUE INDEX idx_name
ON table (column);
```

Создание составного индекса

```sql
CREATE INDEX idx_name
ON table (column1, column2);
```

Создание индекса по выражению

```sql
CREATE INDEX idx_name
ON table (upper(column));
```

Создание частичного индекса

```sql
CREATE INDEX idx_name
ON table (column)
WHERE condition;
```

Просмотр плана выполнения

```sql
EXPLAIN ANALYZE
SELECT ...
```

Отключение последовательного сканирования (для анализа)

```sql
SET enable_seqscan = off;
```
