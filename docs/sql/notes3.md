## Представления (View)

### Что такое View

**View (представление)** — это виртуальная таблица, основанная на результате
SQL-запроса.

Представление не хранит собственные данные. Каждый раз при обращении к нему
выполняется исходный SQL-запрос, после чего возвращается актуальный результат.

Схема работы:

```
Таблицы
     │
     ▼
 SQL-запрос
     │
     ▼
    View
     │
     ▼
 Пользователь
```

---

### Зачем нужны представления

Представления используются для:

- сокрытия сложных SQL-запросов;
- ограничения доступа к данным;
- повторного использования запросов;
- упрощения аналитики;
- разделения логики приложения и структуры базы данных.

---

### Создание представления

Синтаксис:

```sql
CREATE VIEW view_name AS
SELECT ...
FROM ...;
```

Пример:

```sql
CREATE VIEW v_persons_female AS
SELECT *
FROM person
WHERE gender = 'female';
```

Аналогично можно создать представление для мужчин:

```sql
CREATE VIEW v_persons_male AS
SELECT *
FROM person
WHERE gender = 'male';
```

После создания можно выполнять обычные запросы:

```sql
SELECT *
FROM v_persons_female;
```

---

## Использование нескольких представлений

Представления можно объединять между собой.

Например:

```sql
SELECT name
FROM v_persons_female

UNION

SELECT name
FROM v_persons_male

ORDER BY name;
```

Результатом будет единый список всех людей.

---

## Генерация последовательностей данных

В PostgreSQL существует функция:

```sql
generate_series()
```

Она позволяет генерировать:

- числа;
- даты;
- временные интервалы.

Пример генерации дат января:

```sql
SELECT generate_series(
    DATE '2022-01-01',
    DATE '2022-01-31',
    INTERVAL '1 day'
);
```

Результат:

```
2022-01-01
2022-01-02
2022-01-03
...
2022-01-31
```

Такую последовательность можно сохранить в представлении:

```sql
CREATE VIEW v_generated_dates AS
SELECT
    generate_series(
        DATE '2022-01-01',
        DATE '2022-01-31',
        INTERVAL '1 day'
    )::date AS generated_date;
```

---

## Поиск отсутствующих данных

Используя представление с календарем, можно находить пропущенные записи.

Для этого удобно использовать оператор:

```sql
EXCEPT
```

Пример:

```sql
SELECT generated_date
FROM v_generated_dates

EXCEPT

SELECT visit_date
FROM person_visits;
```

Результат:

```
2022-01-11
2022-01-12
...
2022-01-31
```

Таким способом можно быстро находить отсутствующие даты, документы,
пользователей и любые другие данные.

---

## Операции над множествами

SQL поддерживает операции теории множеств.

### UNION

Объединяет результаты двух запросов.

Дубликаты удаляются автоматически.

```sql
SELECT ...

UNION

SELECT ...
```

---

### UNION ALL

Объединяет результаты, сохраняя все строки.

Дубликаты не удаляются.

```sql
SELECT ...

UNION ALL

SELECT ...
```

---

### EXCEPT

Возвращает строки, которые присутствуют в первом запросе, но отсутствуют во
втором.

```sql
SELECT ...

EXCEPT

SELECT ...
```

Используется для поиска различий между наборами данных.

---

### INTERSECT

Возвращает только общие строки двух запросов.

```sql
SELECT ...

INTERSECT

SELECT ...
```

Используется для поиска совпадений.

---

## Симметрическая разность множеств

В SQL можно реализовать выражение:

```
(R − S) ∪ (S − R)
```

Оно возвращает элементы, принадлежащие только одному из множеств.

Пример реализации:

```sql
(
SELECT ...
EXCEPT
SELECT ...
)

UNION

(
SELECT ...
EXCEPT
SELECT ...
);
```

Такой подход часто применяется при сравнении двух выборок данных.

---

## Вычисляемые столбцы

В представления можно добавлять вычисляемые значения.

Например, расчет скидки:

```sql
price - price * 0.1
```

или

```sql
price * 0.9
```

Округление выполняется функцией:

```sql
ROUND()
```

Пример:

```sql
ROUND(price * 0.9)
```

Полученное значение можно сохранить в отдельном столбце:

```sql
discount_price
```

## Материализованные представления

### Что такое Materialized View

Materialized View — это объект базы данных, который хранит результат SQL-запроса
физически.

В отличие от обычного представления данные не пересчитываются при каждом
обращении.

Схема работы:

```
Таблицы
     │
     ▼
 SQL-запрос
     │
     ▼
Materialized View
     │
     ▼
 Пользователь
```

---

### Отличия View и Materialized View

| View                             | Materialized View                            |
| -------------------------------- | -------------------------------------------- |
| Данные не хранятся               | Данные сохраняются                           |
| Всегда актуальные данные         | Данные обновляются вручную или по расписанию |
| Каждый запрос выполняется заново | Используются уже сохраненные данные          |
| Не требует места на диске        | Требует дополнительное место                 |

---

### Создание Materialized View

Синтаксис:

```sql
CREATE MATERIALIZED VIEW view_name AS
SELECT ...
FROM ...;
```

Пример:

```sql
CREATE MATERIALIZED VIEW mv_dmitriy_visits_and_eats AS
SELECT ...
```

После создания данные уже находятся внутри объекта.

---

## Обновление Materialized View

После изменения исходных таблиц материализованное представление автоматически не
обновляется.

Для обновления используется:

```sql
REFRESH MATERIALIZED VIEW mv_dmitriy_visits_and_eats;
```

После выполнения команды представление снова содержит актуальные данные.

---

## Удаление представлений

Удаление обычного представления:

```sql
DROP VIEW view_name;
```

Удаление материализованного представления:

```sql
DROP MATERIALIZED VIEW view_name;
```

После удаления объект исчезает из базы данных.
