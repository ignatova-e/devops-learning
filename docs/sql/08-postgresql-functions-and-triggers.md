# PostgreSQL. Функции, PL/pgSQL и триггеры

## Что такое функции в PostgreSQL

**Функция** — это именованный блок SQL- или PL/pgSQL-кода, который можно
вызывать многократно.

Функции позволяют:

- избегать дублирования SQL-кода;
- переносить бизнес-логику в базу данных;
- выполнять сложные вычисления;
- возвращать одно значение или целые таблицы;
- использовать параметры;
- повышать читаемость запросов.

В PostgreSQL функции могут быть написаны на различных языках:

- SQL;
- PL/pgSQL;
- PL/Python;
- PL/R;
- и других.

На практике чаще всего используются **SQL** и **PL/pgSQL**.

---

# Где должна находиться бизнес-логика?

Существует два основных подхода.

## Бизнес-логика в приложении

Вся логика реализуется на стороне backend.

Преимущества:

- проще тестировать;
- легче поддерживать;
- удобно использовать в микросервисной архитектуре.

Недостаток:

Если кто-то подключится к базе напрямую (например, через pgAdmin или DBeaver),
он сможет изменить данные, минуя проверки приложения.

---

## Бизнес-логика в базе данных

Правила реализуются с помощью:

- функций;
- триггеров;
- ограничений;
- представлений.

Преимущества:

- все приложения работают по одинаковым правилам;
- невозможно обойти проверки, обращаясь напрямую к БД;
- уменьшается количество одинакового кода в разных приложениях.

Недостаток:

Логика распределяется между приложением и базой данных, что усложняет
сопровождение.

---

## Наиболее распространённый подход

В реальных проектах обычно используется комбинированный вариант:

- бизнес-логика приложения располагается в backend;
- критически важные ограничения и проверки — в базе данных.

# SQL-функции

Самый простой тип функций.

Они состоят из одного SQL-запроса.

Пример:

```sql
CREATE FUNCTION fnc_persons_female()
RETURNS TABLE
(
    id bigint,
    name varchar,
    age integer,
    gender varchar,
    address varchar
)
AS $$
    SELECT *
    FROM person
    WHERE gender = 'female';
$$
LANGUAGE sql;
```

Теперь функцию можно вызвать:

```sql
SELECT *
FROM fnc_persons_female();
```

---

# Возвращение таблицы

Функция может возвращать сразу несколько строк.

Используется конструкция:

```sql
RETURNS TABLE (...)
```

Например:

```sql
RETURNS TABLE
(
    id bigint,
    name varchar
)
```

Такая функция работает почти как обычная таблица.

---

# Параметры функции

Функции могут принимать входные параметры.

Пример:

```sql
CREATE FUNCTION fnc_persons
(
    pgender varchar
)
```

Использование:

```sql
SELECT *
FROM fnc_persons('male');
```

или

```sql
SELECT *
FROM fnc_persons('female');
```

---

# Значения параметров по умолчанию

Для параметров можно задать значение по умолчанию.

Например:

```sql
pgender varchar DEFAULT 'female'
```

Теперь функцию можно вызвать двумя способами:

```sql
SELECT *
FROM fnc_persons();
```

или

```sql
SELECT *
FROM fnc_persons('male');
```

---

# PL/pgSQL

**PL/pgSQL** — процедурный язык PostgreSQL.

В отличие от SQL-функций он поддерживает:

- переменные;
- условия;
- циклы;
- обработку исключений;
- сложную бизнес-логику.

Общий шаблон:

```sql
CREATE FUNCTION ...
RETURNS ...
AS $$
BEGIN

    ...

END;
$$
LANGUAGE plpgsql;
```

> Символы `$$` обозначают **долларовое цитирование (Dollar-Quoted String)** —
> специальный способ записи тела функции без необходимости экранировать
> одинарные кавычки.

---

# RETURN QUERY

Если функция возвращает таблицу, используется оператор

```sql
RETURN QUERY
```

Например:

```sql
RETURN QUERY
SELECT ...
```

Результат запроса становится результатом работы функции.

---

# Входные параметры (IN)

Для большей читаемости параметры можно явно обозначить как входные:

```sql
IN pperson varchar
```

или

```sql
IN pprice numeric
```

Все параметры с модификатором `IN` доступны внутри функции только для чтения.

---

# Функции с несколькими параметрами

Функция может принимать сразу несколько аргументов.

Например:

```sql
(
    pperson,
    pprice,
    pdate
)
```

После вызова

```sql
SELECT *
FROM fnc_person_visits_and_eats_on_date(
    'Dmitriy',
    500,
    '2022-01-08'
);
```

будут использованы переданные значения.

---

# VARIADIC

Иногда заранее неизвестно количество аргументов.

Для этого используется

```sql
VARIADIC
```

Пример:

```sql
CREATE FUNCTION func_minimum(
    VARIADIC arr numeric[]
)
```

Теперь функцию можно вызвать так:

```sql
SELECT func_minimum(5, 7, 2, 10, 3);
```

Все аргументы автоматически объединяются в массив.

---

# unnest()

Функция

```sql
unnest()
```

преобразует массив в набор строк.

Например:

```sql
unnest(arr)
```

Массив

```
[5, 7, 2]
```

станет

```
5
7
2
```

После этого можно применять агрегатные функции:

```sql
MIN()
MAX()
AVG()
```

---

# Рекурсивные функции

Функция может использовать рекурсивный запрос (`WITH RECURSIVE`).

Пример — генерация чисел Фибоначчи.

```sql
WITH RECURSIVE
```

позволяет строить последовательности без циклов PL/pgSQL.

Такой подход хорошо подходит для:

- иерархий;
- деревьев;
- графов;
- математических последовательностей.

---

# Триггеры

**Триггер** — это механизм автоматического выполнения функции при наступлении
определённого события.

События:

- `INSERT`;
- `UPDATE`;
- `DELETE`.

Триггер нельзя вызвать вручную — он срабатывает автоматически.

---

# Создание триггера

Сначала создаётся функция:

```sql
CREATE FUNCTION ...
RETURNS trigger
```

Затем триггер:

```sql
CREATE TRIGGER
```

Например:

```sql
CREATE TRIGGER trg_person_insert_audit
AFTER INSERT
ON person
FOR EACH ROW
EXECUTE FUNCTION fnc_trg_person_insert_audit();
```

---

# BEFORE и AFTER

Триггер может выполняться:

## BEFORE

До изменения данных.

Используется для:

- проверки данных;
- изменения значений;
- запрета операции.

---

## AFTER

После успешного изменения данных.

Используется для:

- журналирования;
- логирования;
- отправки уведомлений;
- аудита.

В данном проекте использовались именно `AFTER`-триггеры.

---

# FOR EACH ROW

Существует два режима работы триггеров.

## FOR EACH ROW

Функция вызывается для каждой изменённой строки.

Если обновляется 100 строк — функция выполнится 100 раз.

---

## FOR EACH STATEMENT

Функция вызывается один раз на весь SQL-запрос.

Используется значительно реже.

---

# NEW и OLD

Внутри триггерной функции доступны специальные записи.

## NEW

Содержит новое состояние строки.

Используется при:

- `INSERT`;
- `UPDATE`.

Например:

```sql
NEW.name
```

---

## OLD

Содержит старое состояние строки.

Используется при:

- `UPDATE`;
- `DELETE`.

Например:

```sql
OLD.name
```

---

# TG_OP

Переменная

```sql
TG_OP
```

содержит тип события, вызвавшего триггер.

Возможные значения:

- `INSERT`;
- `UPDATE`;
- `DELETE`.

Это позволяет использовать одну функцию сразу для нескольких событий.

Например:

```sql
IF TG_OP = 'INSERT' THEN
...
ELSIF TG_OP = 'UPDATE' THEN
...
ELSIF TG_OP = 'DELETE' THEN
...
END IF;
```

---

# Аудит изменений

**Аудит** — это сохранение истории изменений данных.

В проекте была создана таблица

```sql
person_audit
```

которая хранит:

- время изменения;
- тип операции;
- идентификатор записи;
- старые значения полей.

При каждом:

- добавлении;
- изменении;
- удалении

триггер автоматически сохраняет информацию.

Такой механизм широко используется:

- в банковских системах;
- медицинских информационных системах;
- CRM;
- ERP;
- бухгалтерском программном обеспечении.

---

# Универсальный триггер

Вместо трёх отдельных функций можно создать одну универсальную.

Она определяет тип операции через

```sql
TG_OP
```

и выполняет необходимое действие.

Такой подход:

- уменьшает количество кода;
- облегчает сопровождение;
- снижает вероятность ошибок.

---

# Удаление триггеров и функций

Удаление триггера:

```sql
DROP TRIGGER trg_name
ON table_name;
```

Удаление функции:

```sql
DROP FUNCTION function_name();
```

# Практические рекомендации

- Используйте SQL-функции для простых запросов и PL/pgSQL — для сложной логики.
- Задавайте значения параметров по умолчанию, если это делает функцию более
  удобной в использовании.
- Применяйте `RETURNS TABLE`, когда функция должна возвращать набор строк.
- Используйте `RETURN QUERY` в PL/pgSQL для возврата результатов запросов.
- Создавайте триггеры только для действительно важных сценариев (аудит,
  автоматическое заполнение полей, контроль бизнес-правил), так как их
  чрезмерное использование может усложнить сопровождение системы.
- Предпочитайте один универсальный триггер нескольким почти одинаковым, если
  логика различается только типом операции.
- Используйте `NEW` и `OLD` только в тех событиях, где они доступны: `NEW` — для
  `INSERT` и `UPDATE`, `OLD` — для `UPDATE` и `DELETE`.
- Документируйте функции и триггеры, особенно если они реализуют важную
  бизнес-логику.
