# PostgreSQL. Ограничения, последовательности, документирование и проектирование БД

## Проектирование базы данных

Качественная база данных начинается не с написания SQL-запросов, а с правильного
проектирования.

При разработке БД необходимо учитывать два важных аспекта:

1. **Логическая модель** — насколько структура базы данных отражает реальные
   бизнес-процессы.
2. **Физическая модель** — насколько эффективно база данных будет работать с
   точки зрения производительности, хранения данных и стоимости эксплуатации.

Хорошая база данных должна одновременно:

- корректно хранить данные;
- обеспечивать их целостность;
- быстро выполнять запросы;
- легко масштабироваться;
- быть понятной другим разработчикам.

---

# Этапы проектирования базы данных

При создании базы данных обычно проходят три этапа:

1. **Проектирование логической модели**
   - определяются сущности;
   - выделяются связи между ними;
   - описываются бизнес-процессы.

2. **Создание физической модели**
   - создаются таблицы;
   - выбираются типы данных;
   - определяются ключи;
   - создаются индексы и ограничения.

3. **Оптимизация**
   - анализируются запросы;
   - создаются дополнительные индексы;
   - проверяется производительность;
   - устраняются узкие места.

---

# Создание новой таблицы

Новая таблица создаётся командой `CREATE TABLE`.

Пример:

```sql
CREATE TABLE person_discounts
(
    id BIGINT PRIMARY KEY,
    person_id BIGINT,
    pizzeria_id BIGINT,
    discount NUMERIC,

    CONSTRAINT fk_person_discounts_person_id
        FOREIGN KEY (person_id)
        REFERENCES person(id),

    CONSTRAINT fk_person_discounts_pizzeria_id
        FOREIGN KEY (pizzeria_id)
        REFERENCES pizzeria(id)
);
```

В таблице используются:

- первичный ключ;
- внешние ключи;
- отдельные ограничения с понятными именами.

---

# Первичный ключ (PRIMARY KEY)

Первичный ключ:

- уникально идентифицирует каждую запись;
- не допускает значение `NULL`;
- автоматически создаёт уникальный индекс.

Пример:

```sql
id BIGINT PRIMARY KEY
```

---

# Внешний ключ (FOREIGN KEY)

Внешний ключ обеспечивает ссылочную целостность данных.

Пример:

```sql
FOREIGN KEY (person_id)
REFERENCES person(id)
```

Теперь нельзя добавить скидку для несуществующего пользователя.

Аналогично:

```sql
FOREIGN KEY (pizzeria_id)
REFERENCES pizzeria(id)
```

Теперь скидка всегда относится к существующей пиццерии.

---

# Заполнение таблицы через INSERT ... SELECT

Данные можно получать не только вручную, но и на основе результатов другого
запроса.

Например:

```sql
INSERT INTO person_discounts (...)
SELECT ...
```

Такой способ называется **массовой вставкой**.

В рассматриваемом проекте скидка рассчитывается автоматически:

```sql
CASE COUNT(*)
    WHEN 1 THEN 10.5
    WHEN 2 THEN 22
    ELSE 30
END
```

Логика:

- 1 заказ → скидка 10.5%;
- 2 заказа → скидка 22%;
- 3 и более → скидка 30%.

Количество заказов определяется при помощи агрегатной функции:

```sql
COUNT(*)
```

Группировка выполняется по клиенту и пиццерии:

```sql
GROUP BY person_id, pizzeria_id
```

---

# ROW_NUMBER()

Функция

```sql
ROW_NUMBER()
```

генерирует последовательную нумерацию строк.

Например:

```sql
ROW_NUMBER() OVER ()
```

Результат:

| id |
| -: |
|  1 |
|  2 |
|  3 |
|  4 |

В проекте она использовалась для формирования значений первичного ключа при
первоначальном заполнении таблицы.

---

# Вычисляемые поля

SQL позволяет рассчитывать значения непосредственно во время выполнения запроса.

Например:

```sql
price * (100 - discount) / 100
```

получает стоимость товара после применения скидки.

Такой столбец существует только в результате запроса и не сохраняется в таблице.

---

# Соединение нескольких таблиц

Для получения полной информации часто требуется объединить несколько таблиц.

Пример:

- `person`
- `person_order`
- `menu`
- `pizzeria`
- `person_discounts`

Соединение выполняется через `JOIN`.

Если скидка зависит одновременно от пользователя и пиццерии, используются сразу
два условия:

```sql
ON person_discounts.person_id = person_order.person_id
AND person_discounts.pizzeria_id = menu.pizzeria_id
```

---

# Уникальный индекс

Для предотвращения появления одинаковых скидок используется уникальный индекс.

```sql
CREATE UNIQUE INDEX idx_person_discounts_unique
ON person_discounts
(
    person_id,
    pizzeria_id
);
```

Теперь одна пиццерия не сможет хранить две разные скидки для одного и того же
клиента.

Такой индекс одновременно:

- ускоряет поиск;
- обеспечивает уникальность данных.

---

# Проверка использования индекса

Для анализа используется:

```sql
EXPLAIN ANALYZE
```

Например:

```sql
EXPLAIN ANALYZE
SELECT *
FROM person_discounts
WHERE person_id = 1
AND pizzeria_id = 1;
```

Для обучения можно отключить последовательное сканирование:

```sql
SET enable_seqscan = OFF;
```

Если индекс подходит, PostgreSQL выполнит поиск через него.

---

# Ограничения (Constraints)

Ограничения позволяют автоматически контролировать корректность данных.

Их главная задача — не допустить появления неверных записей.

---

## CHECK

Проверяет выполнение некоторого условия.

Например:

```sql
CHECK (discount BETWEEN 0 AND 100)
```

Теперь невозможно записать:

```
150%
```

или

```
-25%
```

---

## NOT NULL через CHECK

В проекте отсутствие значения запрещалось при помощи:

```sql
CHECK (person_id IS NOT NULL)
```

Хотя чаще используют конструкцию

```sql
person_id BIGINT NOT NULL
```

Оба способа запрещают хранение `NULL`, однако `NOT NULL` является более
распространённым и читаемым решением.

---

## DEFAULT

Позволяет автоматически подставлять значение.

Например:

```sql
ALTER COLUMN discount
SET DEFAULT 0;
```

Теперь при вставке записи без указания скидки PostgreSQL автоматически установит
значение `0`.

---

# ALTER TABLE

Команда используется для изменения уже существующей таблицы.

Она позволяет:

- добавлять ограничения;
- изменять типы данных;
- задавать значения по умолчанию;
- добавлять новые столбцы;
- удалять ограничения.

Пример:

```sql
ALTER TABLE person_discounts
ADD CONSTRAINT ...;
```

---

# Документирование базы данных

PostgreSQL позволяет добавлять комментарии к объектам базы данных.

Для таблицы:

```sql
COMMENT ON TABLE person_discounts
IS 'Personal discounts offered to customers by pizzerias.';
```

Для столбца:

```sql
COMMENT ON COLUMN person_discounts.discount
IS 'Discount percentage available to the customer.';
```

Комментарии помогают:

- другим разработчикам;
- аналитикам;
- администраторам БД;
- инструментам генерации документации.

Хорошо задокументированная база значительно проще в сопровождении.

---

# Последовательности (SEQUENCE)

Последовательность — специальный объект PostgreSQL, автоматически генерирующий
уникальные числа.

Создание:

```sql
CREATE SEQUENCE seq_person_discounts
START WITH 1;
```

Получение следующего значения:

```sql
nextval('seq_person_discounts')
```

---

# Автоматическая генерация идентификаторов

Последовательность можно связать со столбцом:

```sql
ALTER TABLE person_discounts
ALTER COLUMN id
SET DEFAULT nextval('seq_person_discounts');
```

После этого при добавлении новой записи значение `id` будет генерироваться
автоматически.

Например:

```sql
INSERT INTO person_discounts
(person_id, pizzeria_id, discount)
VALUES
(1, 2, 15);
```

Поле `id` заполнять уже не требуется.

---

# Синхронизация последовательности

Если таблица уже содержит данные, последовательность может выдавать значения,
которые уже существуют.

Для синхронизации используется:

```sql
SELECT setval(
    'seq_person_discounts',
    (SELECT COUNT(*) + 1
     FROM person_discounts),
    false
);
```

Функция `setval()` изменяет текущее значение последовательности.

Это необходимо после:

- массового импорта данных;
- ручной вставки значений первичного ключа;
- восстановления резервной копии.

# Практические рекомендации

- Используйте `PRIMARY KEY` для каждой таблицы.
- Всегда задавайте `FOREIGN KEY`, если между таблицами существуют связи.
- Проверяйте корректность данных с помощью `CHECK`.
- Используйте `DEFAULT` для значений, которые должны подставляться
  автоматически.
- Создавайте уникальные индексы там, где бизнес-логика запрещает дубликаты.
- Для автоматической генерации идентификаторов используйте последовательности.
- После импорта данных синхронизируйте последовательность через `setval()`.
- Документируйте таблицы и столбцы с помощью `COMMENT`, чтобы облегчить
  сопровождение базы данных.
