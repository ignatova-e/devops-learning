# 6. Дополнительные возможности Git

После освоения базового цикла полезно познакомиться с двумя инструментами:
`.gitignore` защищает репозиторий от ненужных файлов, а `git stash` временно
убирает незавершенную работу.

## `.gitignore`: что не нужно хранить в Git

В репозиторий не стоит добавлять зависимости, сборочные артефакты, кэш
редактора, логи и реальные секреты. Правила игнорирования находятся в файле
`.gitignore` в корне проекта.

Пример:

```gitignore
# Локальные настройки и секреты
.env
.env.*
!.env.example

# Зависимости и сборка
node_modules/
dist/

# Логи и временные файлы
*.log
tmp/

# Настройки редакторов и ОС
.vscode/
.DS_Store
```

Основные правила:

| Шаблон         | Значение                                                      |
| -------------- | ------------------------------------------------------------- |
| `*.log`        | игнорировать все файлы с расширением `.log`                   |
| `tmp/`         | игнорировать каталог `tmp`                                    |
| `/build/`      | игнорировать `build` только в корне репозитория               |
| `!example.env` | не игнорировать файл, который подходит под предыдущее правило |

Проверьте, почему файл игнорируется:

```bash
git check-ignore -v .env
git status --ignored
```

`.gitignore` действует только на неотслеживаемые файлы. Если секрет уже был
добавлен в Git, его нужно убрать из индекса и сменить сам секрет:

```bash
git rm --cached .env
git commit -m "chore: stop tracking local environment file"
```

Сам файл останется на компьютере, но перестанет отслеживаться. Если секрет уже
был отправлен на GitHub, считайте его скомпрометированным: отзовите или замените
его, даже если позднее удалили файл из истории.

## Временное сохранение изменений: stash

`git stash` сохраняет незакоммиченные изменения и возвращает рабочую директорию
к чистому состоянию. Это удобно, когда нужно срочно переключиться на другую
задачу, но текущие правки не готовы к коммиту.

```bash
git status
git stash push -m "WIP: update deployment guide"
git status
git stash list
```

По умолчанию stash не включает новые неотслеживаемые файлы. Для них добавьте
`-u`:

```bash
git stash push -u -m "WIP: include new files"
```

Вернуть последнюю запись и удалить ее из списка:

```bash
git stash pop
```

Если хотите применить изменения, но оставить запись на случай ошибки,
используйте `git stash apply`. Для конкретной записи укажите имя из
`git stash list`:

```bash
git stash apply stash@{1}
git stash drop stash@{1}
```

Stash — временный инструмент, а не замена коммитам. Для работы дольше нескольких
минут лучше создать ветку и сохранить понятный WIP-коммит.

## Полезные привычки

- храните в Git только то, что необходимо для запуска и понимания проекта;
- добавляйте `.env.example` без настоящих значений вместо `.env`;
- перед `git clean` всегда запускайте `git clean -n`;
- давайте stash понятные сообщения, иначе через неделю сложно понять их смысл;
- не используйте stash для передачи работы другому человеку — отправьте ветку в
  удаленный репозиторий.

## Практика

Создайте `.gitignore` для `.env`, `*.log` и `tmp/`. Убедитесь через
`git status`, что эти файлы не предлагаются к коммиту, но `.env.example`
остается видимым. Затем измените README, сохраните правку через `git stash`,
проверьте чистое состояние и верните ее командой `git stash pop`.
