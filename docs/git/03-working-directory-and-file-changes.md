# 3. Работа с файлами и анализ изменений

В этой теме — ежедневные команды для контроля состояния файлов. Привычка
смотреть статус и diff перед коммитом защищает историю проекта от случайных
изменений.

## Состояния файлов

Git различает несколько состояний:

| Состояние | Что это означает                                             |
| --------- | ------------------------------------------------------------ |
| Untracked | файл есть на диске, но Git о нем еще не знает                |
| Modified  | отслеживаемый файл изменен в рабочей директории              |
| Staged    | версия файла добавлена в индекс и попадет в следующий коммит |
| Committed | версия сохранена в истории                                   |

Посмотреть текущее состояние:

```bash
git status
git status --short
```

Короткий формат удобен в терминале: первый символ показывает состояние индекса,
второй — состояние рабочей директории. Например, `M README.md` означает
изменение, еще не добавленное в индекс, а `M  README.md` — уже подготовленную
версию.

## Добавление и удаление файлов

```bash
touch NOTES.md
git add NOTES.md
git commit -m "docs: add notes file"

rm NOTES.md
git status
git rm NOTES.md
git commit -m "docs: remove obsolete notes"
```

Обычная команда `rm` удаляет файл только с диска. `git rm` удаляет его из
рабочей директории и одновременно добавляет удаление в индекс. Если файл уже
удален обычной командой, `git add -u` тоже подготовит это удаление.

## Как читать diff

```bash
git diff                 # рабочая директория ↔ индекс
git diff --staged        # индекс ↔ последний коммит
git diff HEAD            # все незакоммиченные изменения ↔ последний коммит
git diff -- README.md    # только один файл
```

В diff строки с `-` удалены, с `+` добавлены. Заголовок `@@` показывает участок
файла. Diff не только помогает проверить код: он полезен для поиска случайных
пробелов, отладочных сообщений и файлов с секретами.

## Индекс: выбираем содержимое коммита

Индекс позволяет сделать несколько логичных коммитов из одной рабочей
директории. Допустим, вы одновременно исправили опечатку в README и поменяли
настройку приложения. Эти изменения лучше сохранить раздельно:

```bash
git add README.md
git diff --staged
git commit -m "docs: fix typo in readme"

git add config.yml
git commit -m "config: update application settings"
```

Не добавляйте все автоматически без проверки. `git add .` удобно для небольшого
и понятного изменения, но перед коммитом все равно выполните
`git diff --staged`. Команда `git commit -am` работает только с уже
отслеживаемыми файлами и не добавит новые.

Когда в одном файле есть независимые правки, используйте интерактивное
добавление:

```bash
git add -p
```

Git покажет изменения частями (hunks) и позволит выбрать, что добавить сейчас.
Клавиша `?` выводит подсказку по доступным ответам.

## Безопасный рабочий ритуал

```bash
git status
git diff
git add <нужные-файлы>
git diff --staged
git commit -m "тип: короткое описание"
git status
```

После последней команды желательно увидеть `working tree clean`. Это означает,
что в рабочей директории нет непреднамеренно оставленных изменений.

## Практика

В тестовом репозитории измените `README.md` и создайте `TODO.md`. Добавьте в
индекс только README, посмотрите оба варианта `git diff`, сделайте коммит. Затем
добавьте и закоммитьте TODO отдельным коммитом. История должна отражать две
независимые задачи.
