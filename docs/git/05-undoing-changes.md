# 5. Отмена изменений

Git позволяет отменять почти любое действие, но команды работают с разными
областями: рабочей директорией, индексом и историей. Перед отменой выполните
`git status` и `git diff`: так вы точно поймете, какие данные затронет команда.

> Команды с `--hard` и `clean` могут безвозвратно удалить локальные файлы.
> Используйте их только в учебном репозитории или после резервной копии.

## Отмена изменений в рабочей директории

Если отслеживаемый файл изменен, но еще не добавлен в индекс:

```bash
git restore README.md
```

Команда вернет версию из индекса и удалит локальные правки этого файла. Для
предварительной проверки используйте `git diff -- README.md`.

Если нужно удалить неотслеживаемые файлы, сначала посмотрите, что будет сделано:

```bash
git clean -nd  # показать файлы и каталоги, ничего не удаляя
git clean -fd  # удалить неотслеживаемые файлы и каталоги
```

`git clean` не возвращает файлы в корзину. Не используйте его для каталогов с
данными, которые не хранятся в Git.

## Убрать файл из индекса

Когда файл случайно добавили через `git add`, но коммита еще нет:

```bash
git restore --staged README.md
git status
```

Правки в рабочей директории останутся; изменится только содержимое индекса.
После этого можно добавить правильную часть изменений через `git add` или
`git add -p`.

## Отмена опубликованного коммита: revert

Для коммита, который уже попал в общий удаленный репозиторий, используйте
`git revert`. Она создает новый коммит с обратными изменениями и не переписывает
историю:

```bash
git log --oneline
git revert <хеш-коммита>
git push
```

Это безопасный вариант для командной работы. Если Git сообщает о конфликте,
разрешите его, добавьте исправленные файлы и выполните `git revert --continue`.

## Reset: изменение локальной истории

`git reset` передвигает текущую ветку на другой коммит. Используйте его для
локальных, еще не опубликованных коммитов:

```bash
git reset --soft HEAD~1   # отменить коммит, оставить изменения в индексе
git reset --mixed HEAD~1  # отменить коммит, оставить изменения в рабочей директории
git reset --hard HEAD~1   # отменить коммит и удалить локальные изменения
```

`--mixed` — режим по умолчанию. После `reset --hard` простого способа вернуть
незакоммиченные правки нет. Не делайте `push --force` в общую ветку без явной
договоренности команды.

## Исправление последнего локального коммита

Если коммит только что создан и еще не отправлен, можно дополнить его или
исправить сообщение:

```bash
git add README.md
git commit --amend --no-edit

# или изменить сообщение коммита
git commit --amend -m "docs: improve project readme"
```

`--amend` создает новый коммит вместо предыдущего, поэтому его хеш меняется.
После публикации это тоже переписывание истории; для общей ветки обычно лучше
сделать отдельный исправляющий коммит.

## Выбор команды

| Ситуация                                    | Подход                           |
| ------------------------------------------- | -------------------------------- |
| Ошибка только в рабочем файле               | `git restore <файл>`             |
| Файл добавлен в индекс случайно             | `git restore --staged <файл>`    |
| Нужно отменить общий коммит                 | `git revert <хеш>`               |
| Нужно переделать последний локальный коммит | `git commit --amend`             |
| Нужно убрать локальный коммит               | `git reset` с подходящим режимом |

## Практика

В отдельном учебном репозитории измените файл и отмените правку через
`git restore`. Затем создайте тестовый коммит и отмените его через `git revert`.
Посмотрите `git log --oneline`: в истории должны остаться и исходный, и
отменяющий коммиты.
