# 4. История изменений и навигация

История Git помогает понять, почему появился код, найти изменение, вызвавшее
ошибку, и временно посмотреть старую версию проекта. Начинайте анализ с команд,
которые ничего не меняют: `log`, `show`, `diff` и `grep`.

## Просмотр коммитов

```bash
git log
git log --oneline
git log --oneline --graph --decorate --all
git log -p -- README.md
```

`--oneline` выводит сокращенный хеш и сообщение. `--graph` рисует ветвления,
`--decorate` показывает имена веток и теги. Ключ `-p` добавляет diff каждого
коммита; ограничение после `--` оставляет историю только указанного файла.

Если вывод открыт в просмотрщике `less`, используйте `/текст` для поиска, `n`
для следующего результата и `q` для выхода.

## Изучение конкретного коммита

```bash
git show <хеш>
git show --stat <хеш>
git diff <старый-хеш> <новый-хеш>
git blame README.md
```

`git show` показывает метаданные и изменения коммита. `--stat` дает короткую
сводку по файлам. `git blame` показывает, какой коммит последним изменил каждую
строку. Используйте его как инструмент исследования, а не поиска виноватого:
контекст изменения обычно важнее автора строки.

## Поиск в проекте и в истории

```bash
git grep "DATABASE_URL"
git grep -n -i "todo"
git log -S "old_function_name" --oneline
git log --all --grep="deploy" --oneline
```

`git grep` ищет в отслеживаемых файлах текущей версии. `git log -S` находит
коммиты, где изменилось число вхождений строки. Это полезно, когда нужно понять,
когда функция или настройка появилась либо исчезла.

## Переход к старому коммиту

Чтобы просто посмотреть прошлую версию, переключитесь на хеш:

```bash
git switch --detach <хеш>
git status
git switch main
```

В режиме `detached HEAD` вы не находитесь на ветке. Можно читать и тестировать
код, но не стоит начинать постоянную работу: новый коммит будет трудно найти
позже. Если из старой версии нужно продолжить работу, сразу создайте ветку:

```bash
git switch -c fix/from-old-version <хеш>
```

Для ссылок на коммиты удобно использовать относительные имена:

```bash
git show HEAD        # текущий коммит
git show HEAD~1      # родитель текущего коммита
git show main        # последний коммит ветки main
```

## Практика

Сделайте несколько коммитов в учебном репозитории. Выведите граф истории,
посмотрите diff одного коммита через `git show`, а затем временно переключитесь
на предыдущий коммит и вернитесь в `main`. После этого `git status` должен
показывать ветку `main` и чистую рабочую директорию.
