# Парадигмы программирования, процессы и asyncio в Python

## 1. Парадигмы программирования

Парадигма программирования — общий способ организации программы и мышления о
данных, состоянии и поведении. Python не требует придерживаться единственного
стиля: в одном приложении можно сочетать функции, объекты, неизменяемые
преобразования данных и конкурентное выполнение.

Такой язык называют мультипарадигмальным. Выбор подхода зависит не от моды, а от
характера задачи:

- последовательность команд удобно выразить процедурно;
- связанные данные и поведение — объектами;
- цепочку преобразований — функционально;
- независимые длительные операции — конкурентно.

Хорошая архитектура может использовать несколько подходов, если у каждого из
них есть понятная роль.

## 2. Процедурный подход

В процедурном стиле программа разбивается на функции, каждая из которых
выполняет отдельную операцию. Главная функция управляет их последовательностью:

```python
def read_numbers() -> list[int]:
    return list(map(int, input().split()))


def calculate_average(numbers: list[int]) -> float:
    if not numbers:
        raise ValueError("numbers must not be empty")
    return sum(numbers) / len(numbers)


def main() -> None:
    numbers = read_numbers()
    print(calculate_average(numbers))


if __name__ == "__main__":
    main()
```

Преимущества подхода:

- простой поток выполнения;
- небольшие функции легко проверять;
- ввод, вычисления и вывод можно разделить;
- мало вспомогательных конструкций.

Процедурный код становится сложным, когда множество функций изменяет общее
состояние и неясно, кто отвечает за его корректность. Тогда данные полезно
объединить с относящимся к ним поведением.

## 3. Объектно-ориентированный подход

Объект объединяет состояние и операции над ним. Класс описывает структуру и
поведение объектов:

```python
class DownloadResult:
    def __init__(self, url: str, success: bool) -> None:
        self.url = url
        self.success = success

    def status_text(self) -> str:
        return "success" if self.success else "error"
```

Основные понятия ООП:

- инкапсуляция — объект управляет своим состоянием через определённый интерфейс;
- наследование — новый класс расширяет или уточняет существующий;
- полиморфизм — разные объекты поддерживают общий интерфейс;
- композиция — объект содержит другие объекты и делегирует им часть работы.

В Python композиция часто проще и гибче глубокой иерархии наследования.
Наследование оправдано, если действительно существует отношение «является» и
подкласс сохраняет контракт базового класса.

### Классы данных

Если класс в основном хранит значения, удобно использовать `dataclass`:

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class User:
    name: str
    role: str
```

Декоратор автоматически создаёт `__init__`, `__repr__` и сравнение объектов.
Параметр `frozen=True` запрещает обычное изменение полей после создания. Такая
неизменяемость уменьшает число неожиданных изменений состояния, хотя не делает
автоматически неизменяемыми вложенные изменяемые объекты.

### Свойства

`property` позволяет предоставить вычисляемое значение как атрибут:

```python
@dataclass(frozen=True)
class Question:
    text: str

    @property
    def words(self) -> list[str]:
        return self.text.split()
```

К свойству обращаются как `question.words`, хотя при этом выполняется метод.
Свойства лучше использовать для недорогих и предсказуемых вычислений без
побочных эффектов.

## 4. Функциональный стиль

Функциональный стиль рассматривает вычисление как преобразование входных данных
в результат. Его важные идеи:

- чистые функции;
- неизменяемые данные;
- функции как значения;
- композиция небольших преобразований;
- минимизация скрытого состояния.

Чистая функция при одинаковых аргументах возвращает одинаковый результат и не
изменяет внешнее состояние:

```python
def failure_rate(total: int, failed: int) -> float:
    return failed / total if total else 0.0
```

Чистые функции удобно тестировать и безопасно вызывать из разных частей
программы. Чтение файла, сетевой запрос, вывод и генерация случайных чисел имеют
побочные эффекты, но их можно вынести к границам приложения, сохранив основную
логику чистой.

### Функции как объекты

Функцию можно передать другой функции, сохранить в переменной или вернуть:

```python
def transform(values: list[int], operation) -> list[int]:
    return [operation(value) for value in values]


doubled = transform([1, 2, 3], lambda value: value * 2)
```

Для небольших преобразований Python предлагает `map()` и `filter()`, однако
списковые включения часто читаются проще:

```python
even_squares = [value**2 for value in values if value % 2 == 0]
```

### Неизменяемые преобразования

Вместо изменения исходного списка можно создать новый:

```python
ordered = sorted(users, key=lambda user: user.name)
```

`sorted()` возвращает новую коллекцию, а `list.sort()` меняет существующую.
Неизменяемость требует дополнительной памяти, но упрощает рассуждение о
состоянии, особенно в конкурентной программе.

Не следует искусственно заменять понятный цикл длинной цепочкой `map()` и
`filter()`. Функциональный стиль ценен управляемостью данных, а не отсутствием
ключевого слова `for`.

## 5. Разделение логики и побочных эффектов

Удобная структура приложения состоит из трёх слоёв:

```text
ввод и внешние системы
          ↓
чистая предметная логика
          ↓
вывод и сохранение результата
```

Например, парсер читает файл и создаёт объекты, функция рассчитывает результат,
а отдельный компонент форматирует отчёт. Это позволяет проверять вычисления без
реальных файлов, сети, задержек и терминала.

Зависимость с побочным эффектом можно передать аргументом:

```python
import random
from collections.abc import Sequence


def choose_item(items: Sequence[str], rng: random.Random) -> str:
    return rng.choice(items)
```

В обычной программе передаётся случайный генератор, а в тесте — генератор с
фиксированным seed. Это пример внедрения зависимости без специального
фреймворка.

## 6. Конкурентность, параллелизм и асинхронность

Термины описывают разные свойства:

- последовательное выполнение — в момент времени развивается одна задача;
- конкурентность — несколько задач находятся в процессе выполнения и
  чередуются;
- параллелизм — несколько вычислений физически выполняются одновременно;
- асинхронность — задача может приостановиться в ожидании события, не блокируя
  весь поток выполнения.

Конкурентность относится к организации программы, параллелизм — к фактическому
исполнению. Асинхронная программа обычно конкурентна, но необязательно выполняет
Python-код параллельно.

## 7. Как выбрать механизм выполнения

Характер нагрузки определяет инструмент:

| Нагрузка | Подход |
| --- | --- |
| Много ожидания сети, сокетов или таймеров | `asyncio` |
| Блокирующий I/O без async-интерфейса | потоки или `asyncio.to_thread()` |
| Тяжёлые вычисления на нескольких ядрах CPU | процессы |
| Один простой последовательный сценарий | обычные функции |

Это ориентир, а не абсолютное правило. Нужно учитывать поддержку библиотек,
стоимость передачи данных, число задач и ограничения внешней системы.

### GIL в CPython

В обычной сборке CPython Global Interpreter Lock позволяет одному потоку в
процессе исполнять байткод Python в конкретный момент. Поэтому потоки обычно не
ускоряют чистые CPU-bound вычисления. Во время блокирующего I/O или внутри
некоторых расширений GIL освобождается, поэтому потоки хорошо подходят для
многих операций ожидания.

Отдельные процессы имеют собственные интерпретаторы и могут использовать
несколько ядер. За это приходится платить запуском процессов, отдельной памятью
и сериализацией данных.

## 8. Процессы через `multiprocessing`

Модуль `multiprocessing` создаёт дочерние процессы:

```python
import multiprocessing as mp


def worker(name: str) -> None:
    print(f"worker {name} started")


def main() -> None:
    process = mp.Process(target=worker, args=("first",))
    process.start()
    process.join()


if __name__ == "__main__":
    main()
```

`start()` запускает процесс, `join()` ждёт его завершения. После `join()` можно
проверить `process.exitcode`.

Защитное условие `if __name__ == "__main__"` обязательно для переносимого кода.
При методе запуска `spawn` дочерний процесс импортирует главный модуль. Если
создание процессов выполняется на верхнем уровне, импорт будет снова создавать
процессы.

Для приложений, упакованных в исполняемый файл, может понадобиться:

```python
if __name__ == "__main__":
    mp.freeze_support()
    main()
```

## 9. Методы запуска процессов

Основные start methods:

- `spawn` запускает новый интерпретатор и импортирует модуль;
- `fork` копирует текущий процесс средствами ОС;
- `forkserver` просит отдельный сервер создавать дочерние процессы.

Доступность и значение по умолчанию зависят от ОС и версии Python. Явный
контекст делает решение предсказуемее:

```python
context = mp.get_context("spawn")
process = context.Process(target=worker)
```

При `spawn` функция-цель и передаваемые аргументы должны сериализоваться через
`pickle`. Локальные функции, lambda и некоторые системные объекты передать
нельзя. Определяйте worker-функции на уровне модуля.

## 10. Память и обмен между процессами

Обычные глобальные переменные не являются общей памятью процессов. Изменение
словаря в дочернем процессе не обновит исходный словарь родителя.

Для обмена используются:

- `Queue` — поток сообщений;
- `Pipe` — соединение между концами канала;
- `Value` и `Array` — простые объекты общей памяти;
- `shared_memory` — общий блок памяти;
- `Manager` — прокси к управляемым объектам;
- файлы, сокеты, базы данных и внешние очереди.

Часто проще не разделять изменяемое состояние, а передавать сообщения одному
владельцу состояния.

### Очередь задач

Несколько workers могут брать элементы из общей очереди:

```python
def worker(tasks: mp.Queue, results: mp.Queue) -> None:
    while True:
        item = tasks.get()
        if item is None:
            break
        results.put(process_item(item))
```

Специальное значение `None` здесь служит sentinel — сигналом завершения. Обычно
нужен один sentinel на каждый worker, иначе часть процессов продолжит ждать.

### Очередь событий

Worker может сообщать родителю о смене состояния:

```python
events.put(("started", worker_name, item_id))
events.put(("finished", worker_name, item_id, result))
```

Родитель последовательно читает события и единолично обновляет сводное
состояние. Это архитектура single writer: она уменьшает потребность в
блокировках и делает обновления интерфейса согласованными.

Для большой системы вместо неформальных кортежей полезны `dataclass`, `Enum` или
типизированные сообщения.

## 11. Синхронизация и гонки

Race condition возникает, когда результат зависит от непредсказуемого порядка
конкурентных операций. Например, две задачи могут одновременно прочитать одно
значение счётчика, увеличить его и потерять одно обновление.

Для координации применяются:

- `Lock` и `RLock` — взаимоисключение;
- `Semaphore` — ограничение числа одновременных операций;
- `Event` — сигнал состояния;
- `Condition` — ожидание условия;
- очереди — передача данных с готовой синхронизацией.

Блокировка должна защищать минимальный участок и всегда освобождаться:

```python
with lock:
    shared_counter.value += 1
```

Чем меньше общей изменяемой памяти, тем меньше вероятность deadlock и гонок.

## 12. Корректное завершение процессов

Родитель должен дождаться всех дочерних процессов и обработать ошибки. Иначе
возможны зависшие процессы и неполный результат.

Практические правила:

- предусмотреть явный сигнал завершения;
- вызывать `join()` для запущенных процессов;
- проверять `exitcode`;
- не ждать бесконечно без необходимости: использовать timeout;
- корректно реагировать на `KeyboardInterrupt`;
- использовать `terminate()` только как аварийный механизм;
- не завершать процесс во время записи общего ресурса.

`multiprocessing.Pool` и `ProcessPoolExecutor` удобнее ручного управления, когда
нужно применить функцию ко множеству независимых входов:

```python
from concurrent.futures import ProcessPoolExecutor


with ProcessPoolExecutor() as executor:
    results = list(executor.map(cpu_heavy_function, values))
```

## 13. Время в конкурентных программах

Для измерения длительности используют монотонные часы:

```python
import time

started_at = time.monotonic()
perform_operation()
elapsed = time.monotonic() - started_at
```

`time.time()` представляет календарное время и может измениться из-за
синхронизации системных часов. `time.monotonic()` не движется назад и поэтому
подходит для таймеров, timeout и измерения интервалов.

`time.sleep()` блокирует текущий поток. В отдельном worker-процессе это может
быть нормально; внутри event loop следует применять `await asyncio.sleep()`.

## 14. Случайность и воспроизводимость

Модуль `random` создаёт псевдослучайные последовательности. Для случайного
выбора с весами:

```python
choice = rng.choices(items, weights=weights, k=1)[0]
```

Требования к весам:

- их число совпадает с числом элементов;
- веса неотрицательны;
- хотя бы один вес положителен.

Нормировать сумму к единице необязательно: `random.choices()` использует
относительные величины.

Отдельный генератор удобнее глобальных функций:

```python
rng = random.Random(42)
```

Фиксированный seed делает тест воспроизводимым. В рабочих процессах одинаковый
seed создаст одинаковые последовательности, поэтому генераторы инициализируют
отдельно. Модуль `random` не подходит для паролей и токенов; для безопасности
используют `secrets`.

### Последовательное распределение остатка

Некоторые модели строят веса, последовательно забирая долю от оставшейся массы:

```python
def decreasing_weights(size: int, ratio: float) -> list[float]:
    if size < 1 or ratio <= 1:
        raise ValueError("invalid parameters")

    remaining = 1.0
    weights = []

    for _ in range(size - 1):
        weight = remaining / ratio
        weights.append(weight)
        remaining -= weight

    weights.append(remaining)
    return weights
```

Для предпочтения конца последовательности достаточно развернуть веса, а не
исходные данные. Модель следует документировать: математически корректное
распределение не гарантирует, что оно реалистично описывает поведение людей или
систем.

## 15. Агрегация результатов

После конкурентной обработки часто нужно получить лучшие, худшие или средние
значения. Сначала вычисляют метрику для каждого объекта, затем экстремум:

```python
rates = {
    worker.name: worker.failed / worker.total
    for worker in workers
    if worker.total > 0
}

best_rate = min(rates.values(), default=None)
best_workers = [
    name for name, rate in rates.items()
    if rate == best_rate
]
```

`default` помогает обработать пустой набор. Сравнение результатов `float` на
точное равенство может быть ненадёжным после сложных вычислений; для таких
случаев используют `math.isclose()` или сравнивают исходные целые отношения.

При сортировке удобно задать порядок статусов отдельным словарём:

```python
status_order = {"waiting": 0, "success": 1, "failed": 2}
ordered = sorted(items, key=lambda item: status_order[item.status])
```

## 16. Обновление терминального интерфейса

ANSI-последовательности позволяют очищать терминал и перемещать курсор:

```python
import sys


def clear_screen() -> None:
    if sys.stdout.isatty():
        print("\033[2J\033[H", end="")
```

`isatty()` предотвращает управляющие коды в файле или перенаправленном выводе.
Для сложного интерфейса лучше использовать `rich`, `textual` или `curses`, чем
самостоятельно управлять шириной Unicode-строк и курсором.

Отображение должно быть отделено от workers. Несколько процессов, одновременно
печатающих таблицы, создадут перемешанный вывод. Надёжнее передавать события
родителю и поручить ему единолично обновлять интерфейс.

## 17. Асинхронная модель `asyncio`

`asyncio` организует конкурентное выполнение корутин в одном потоке с помощью
цикла событий. Корутина объявляется через `async def`:

```python
import asyncio


async def operation() -> str:
    await asyncio.sleep(1)
    return "done"


async def main() -> None:
    result = await operation()
    print(result)


if __name__ == "__main__":
    asyncio.run(main())
```

Вызов async-функции создаёт объект корутины, но не выполняет её до `await`,
создания задачи или передачи циклу событий.

`await` приостанавливает текущую корутину до готовности результата. В это время
event loop может продолжить другую готовую задачу. Если внутри корутины вызвать
долгую обычную функцию, весь event loop будет заблокирован.

## 18. Корутины и задачи

Последовательные `await` выполняют операции по очереди:

```python
first = await fetch(first_url)
second = await fetch(second_url)
```

Для конкурентного запуска создают задачи:

```python
first_task = asyncio.create_task(fetch(first_url))
second_task = asyncio.create_task(fetch(second_url))

first, second = await asyncio.gather(first_task, second_task)
```

Задача планирует корутину в event loop. `asyncio.gather()` ждёт группу awaitable
и возвращает результаты в порядке аргументов, а не в порядке завершения.

По умолчанию первое необработанное исключение из `gather()` передаётся
вызывающему коду. `return_exceptions=True` превращает исключения в элементы
результата, но затем их обязательно нужно проверить.

В современных версиях Python для группы связанных задач полезен
`asyncio.TaskGroup`: при ошибке одной задачи он отменяет остальные и формирует
структурированную область конкурентности.

```python
async with asyncio.TaskGroup() as group:
    tasks = [group.create_task(fetch(url)) for url in urls]
```

## 19. Блокирующий код внутри `asyncio`

Библиотека `requests` выполняет блокирующие HTTP-запросы. Прямой вызов
`requests.get()` внутри `async def` остановит весь event loop до завершения
запроса.

Блокирующую функцию можно вынести в worker thread:

```python
async def download(url: str) -> bytes:
    return await asyncio.to_thread(download_sync, url)
```

`asyncio.to_thread()` подходит для совместимости с блокирующим I/O. Он не
делает функцию неблокирующей — она продолжает блокироваться, но в другом потоке.
Для большого числа HTTP-запросов эффективнее использовать асинхронный клиент,
например `aiohttp` или `httpx.AsyncClient`, с повторным использованием сессии.

## 20. Асинхронный пользовательский ввод

Обычный `input()` блокирует поток event loop. Его также можно перенести в поток:

```python
async def async_input(prompt: str) -> str:
    return await asyncio.to_thread(input, prompt)
```

Теперь программа может принимать следующую строку, пока уже созданные задачи
продолжают сетевые операции. Однако одновременно запускать несколько `input()`
не следует: они будут конкурировать за один терминал.

Интерактивная программа должна корректно обрабатывать EOF и прерывание
пользователем:

```python
try:
    asyncio.run(main())
except (EOFError, KeyboardInterrupt):
    print("\nOperation interrupted")
```

## 21. Ограничение конкурентности

Создание десятков тысяч задач одновременно может исчерпать файловые
дескрипторы, память или лимиты сервера. Семафор ограничивает число активных
операций:

```python
semaphore = asyncio.Semaphore(10)


async def limited_download(url: str) -> bytes:
    async with semaphore:
        return await download(url)
```

Другой вариант — фиксированное число worker-корутин, читающих задания из
`asyncio.Queue`. Он удобен для потока входящих задач неизвестной длины.

Ограничение должно учитывать требования удалённого API, пропускную способность,
число соединений и локальные ресурсы. Больше конкурентных задач не всегда
означает быстрее.

## 22. Timeout, отмена и повторные попытки

Сетевая операция не должна ждать бесконечно. В Python можно ограничить время:

```python
async with asyncio.timeout(30):
    result = await operation()
```

При отмене задачи в ней возникает `asyncio.CancelledError`. Очистку ресурсов
размещают в `finally` или доверяют async-контекстным менеджерам. Не следует
безусловно поглощать отмену, иначе приложение не сможет корректно завершиться.

Повторные попытки подходят для временных ошибок, но требуют:

- ограниченного числа повторов;
- увеличивающейся задержки (exponential backoff);
- случайного jitter, чтобы клиенты не повторяли запрос одновременно;
- проверки, безопасно ли повторять операцию;
- различения временных и постоянных ошибок.

Ошибка авторизации или некорректный URL обычно не исправятся повтором.

## 23. Загрузка данных по HTTP

Надёжный загрузчик должен учитывать больше, чем вызов `get()`:

- timeout соединения и чтения;
- HTTP-коды ошибок;
- редиректы;
- максимальный допустимый размер;
- потоковую запись вместо загрузки всего ответа в память;
- проверку типа содержимого, если ожидается определённый формат;
- безопасное имя файла;
- конфликт одинаковых имён;
- частично записанный файл;
- ограничение конкурентности.

Пример блокирующей потоковой загрузки:

```python
import requests


def download_sync(url: str, target: Path) -> None:
    with requests.get(url, timeout=30, stream=True) as response:
        response.raise_for_status()

        with target.open("wb") as output:
            for chunk in response.iter_content(chunk_size=64 * 1024):
                if chunk:
                    output.write(chunk)
```

`raise_for_status()` превращает ошибочные HTTP-статусы в исключение. Потоковый
режим ограничивает расход памяти, но без отдельной проверки всё ещё позволяет
скачать файл произвольного размера.

## 24. Безопасное имя файла из URL

URL нужно разбирать специализированной функцией:

```python
from pathlib import Path
from urllib.parse import unquote, urlparse


def name_from_url(url: str, fallback: str) -> str:
    name = Path(unquote(urlparse(url).path)).name
    return name if name not in {"", ".", ".."} else fallback
```

`Path(...).name` отбрасывает каталоги из URL-пути, но этого недостаточно для
недоверенного ввода во всех системах. Нужно также учитывать:

- запрещённые в целевой ОС символы;
- слишком длинные имена;
- управляющие символы;
- одинаковые имена у разных URL;
- отсутствие расширения;
- несовпадение расширения и фактического содержимого.

Серверный `Content-Disposition` также нельзя использовать без очистки.

## 25. Проверка каталога назначения

`Path.is_dir()` подтверждает существование каталога, но отдельная проверка прав
через `os.access()` подвержена гонке: состояние может измениться до записи.
Надёжнее выполнить реальную пробную операцию и обработать `OSError`:

```python
import os
import tempfile
from pathlib import Path


def validate_directory(path: Path) -> bool:
    try:
        descriptor, probe = tempfile.mkstemp(
            prefix=".write-test-",
            dir=path,
        )
        os.close(descriptor)
        Path(probe).unlink()
        return True
    except OSError:
        return False
```

Если приложение само должно создать каталог, используют
`path.mkdir(parents=True, exist_ok=True)` и всё равно обрабатывают ошибку.

## 26. Атомарное сохранение

Если писать сразу в итоговый файл, после сетевой ошибки может остаться
повреждённый результат. Безопаснее писать во временный файл в том же каталоге и
после успеха заменить целевой:

```python
temporary = target.with_suffix(target.suffix + ".part")

try:
    write_content(temporary)
    temporary.replace(target)
except OSError:
    temporary.unlink(missing_ok=True)
    raise
```

Переименование внутри одной файловой системы обычно атомарно: наблюдатель видит
либо старый целый файл, либо новый. Уникальное временное имя предотвращает
конфликт параллельных загрузок.

При безусловном `replace()` существующий файл может быть перезаписан. Политика
конфликтов должна быть явной: запрещать замену, добавлять уникальный суффикс или
перезаписывать с подтверждением.

## 27. Обработка ошибок и сводка результатов

В пакетной обработке ошибка одного элемента не всегда должна завершать всё
приложение. Worker может вернуть структурированный результат:

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Result:
    source: str
    success: bool
    error: str | None = None
```

Следует ловить ожидаемые исключения на том уровне, где известно, что с ними
делать:

```python
try:
    download_sync(url, target)
except requests.RequestException as error:
    return Result(url, False, str(error))
except OSError as error:
    return Result(url, False, str(error))
else:
    return Result(url, True)
```

Пустой `except Exception` может скрыть ошибки программирования. Если пакетная
система всё же должна изолировать любую ошибку элемента, исключение необходимо
записать с traceback, а `KeyboardInterrupt` и системные сигналы не следует
выдавать за обычную ошибку данных.

Итоговая сводка должна сохранять связь между входом, статусом и причиной ошибки.
Один `bool` удобен для подсчёта, но недостаточен для диагностики.

## 28. Типизация конкурентного кода

Аннотации помогают описать сообщения и результаты:

```python
from collections.abc import Sequence


def calculate(values: Sequence[float]) -> float:
    ...
```

`Sequence` выражает требование индексируемой последовательности, не заставляя
передавать именно список. Для точных структур событий можно применять:

- `dataclass`;
- `NamedTuple`;
- `TypedDict`;
- `Enum` для ограниченного набора состояний;
- объединения типов для разных видов сообщений.

Аннотации не обеспечивают автоматическую проверку во время выполнения. Для
статического анализа используют mypy, pyright или возможности IDE.

## 29. Тестирование

Конкурентный код проще тестировать, если предметная логика отделена от механизма
выполнения.

Полезные уровни проверки:

1. чистые функции: веса, выбор статуса, агрегация;
2. парсинг и форматирование на временных файлах;
3. worker с контролируемыми входами;
4. интеграция процессов и очередей с короткими timeout;
5. async-код с тестовым HTTP-сервером;
6. корректная отмена и частичные ошибки.

Вместо реального `sleep()` зависимости времени можно передавать или заменять в
тесте. Случайность фиксируют seed или подменяют генератор. Сетевые тесты не
должны зависеть от случайного публичного сайта: локальный сервер быстрее и
стабильнее.

Обязательно проверяют границы:

- пустые входные коллекции;
- один worker и задач меньше, чем workers;
- worker завершился с ошибкой;
- очередь временно пуста;
- все HTTP-запросы завершились ошибкой;
- два URL дают одинаковое имя файла;
- пользователь прервал программу;
- каталог стал недоступен во время записи.

## 30. Практические рекомендации

- Выбирайте парадигму под конкретную часть задачи.
- Держите вычисления отдельно от файлов, сети, времени и терминала.
- Не разделяйте изменяемое состояние между процессами без необходимости.
- Передавайте события и назначайте одного владельца сводного состояния.
- Используйте `time.monotonic()` для длительностей.
- Защищайте точку запуска `if __name__ == "__main__"`.
- Не вызывайте блокирующий код непосредственно в event loop.
- Ограничивайте число одновременных сетевых операций.
- Устанавливайте timeout и продумывайте отмену.
- Сохраняйте файлы через временный файл и атомарную замену.
- Не доверяйте имени файла, полученному из URL или HTTP-заголовка.
- Возвращайте подробный результат вместо потери причины ошибки.
- Делайте случайные модели воспроизводимыми в тестах.

Многопарадигмальность Python позволяет выбрать наиболее понятную модель для
каждого слоя: объекты описывают предметные сущности, чистые функции выполняют
вычисления, процессы используют несколько ядер, а `asyncio` эффективно
организует множество операций ожидания.
